# 一、项目摘要

“映人生”是一款以 Android 移动端为核心的 AI 故事内容创作解决方案，面向普通内容创作者、网文/短视频创作者、校园创作人群、文旅与教育等内容运营场景，帮助用户把自拍、人物照片、故事大纲或小说片段转化为角色设定、故事草稿、漫画分镜、短视频脚本与首版视频预览。项目当前不包含面向用户的 Web 平台或 Web 管理后台，产品主入口为 Android App，后端服务负责账号、项目、素材、AI 生成、任务状态、作品、订单、会员与运维支撑。

从行业趋势看，生成式 AI 正在重构内容生产链路，但普通用户在创作过程中仍面临“不会写、不会拆分镜、不会做视觉提示词、不会把文本变成短视频”的门槛。通用大模型虽然具备生成能力，却缺少面向名著融合、角色穿越、小说改编等场景的移动端创作闭环。映人生选择从 Android 移动端切入，让用户在手机上完成场景选择、素材上传、文本输入、AI 访谈、风格选择、故事草稿确认、分镜预览、导出与作品管理，降低创作进入门槛，并通过后端服务统一承接素材存储、任务编排、模型调用、数据沉淀与商业化计费。

项目当前 Android 工程采用 Kotlin、Jetpack Compose、Material 3、Single Activity、多模块结构，已划分 `app`、`core`、`data`、`feature`、`sync`、`benchmark` 等模块，并完成首页、创作入口、场景选择、素材导入、AI 访谈、风格选择、故事草稿、分镜、预览、导出方案、支付确认、作品、订单、会员、个人中心、机构入口等移动端页面骨架。后端采用 FastAPI、Pydantic、SQLAlchemy，支持 MySQL 与 SQLite，已实现认证、用户、场景、项目、上传、素材、AI 创作、任务、预览、导出、作品、订单、会员等接口，并接入阿里云百炼 DashScope 文本、图像、视频、TTS 模型配置。其中，文本创作链路可在未配置 API Key 时返回本地演示结果，预览链路在配置模型能力后可通过图像生成与图生视频生成首版预览。

本项目的核心价值不是单一 App 功能，而是“Android 移动端交互 + 后端业务服务 + 数据沉淀 + AI 生成能力 + 运维体系”的完整移动端解决方案：Android 端负责触达、输入、素材采集、流程引导与结果展示；后端负责业务规则、数据统一管理、AI 调度、任务状态、导出与商业化闭环；数据层沉淀用户创作项目、素材、任务、草稿、分镜、作品、订单与会员权益；算法层输出故事草稿、分镜脚本、封面首帧、短视频预览和后续可扩展的语音、字幕、角色一致性能力。

商业上，项目可从 C 端单次导出、会员订阅、高清无水印导出、增值生成包切入，并逐步扩展到校园创作、文旅内容、教育写作、IP 衍生内容、内容机构批量创作等 B 端或 B2B2C 场景。当前项目仍处于开发与验证阶段，真实用户规模、营收、合作客户、知识产权、测试报告、模型效果评测等需要补充。项目书后文将对缺失信息以【待补充】标注，避免虚构事实。

映人生当前聚焦“自拍/照片 + 大纲/小说 + AI 叙事/分镜/视频预览”的移动创作场景，重点解决普通用户从创意到可展示内容之间的执行断层。

## 4. 现有方案不足

| 痛点类型 | 现有问题 | 与本项目方案的对应关系 |
|---|---|---|
| 技术痛点 | 用户需要同时会写故事、拆分镜、写提示词、设计角色，门槛较高 | Android 端用场景选择、AI 访谈、风格选择降低输入难度；后端统一生成草稿和分镜 |
| 用户痛点 | 普通用户不知道如何把自拍、大纲或小说变成可展示内容 | 移动端按“角色穿越、大纲成文、小说改编”组织流程 |
| 商业痛点 | 单一模板产品复购弱，通用 AI 产品难以形成导出和会员闭环 | 项目设计单次导出、会员、高清无水印、增值模块等收费路径 |
| 生态痛点 | 多个 AI 工具分散，用户需要在不同平台间搬运素材 | 后端通过统一接口整合文本、图像、视频、TTS 等能力 |
| 安全与合规痛点 | 用户照片、肖像、AI 生成内容、版权边界容易被忽视 | Android 端可嵌入协议确认、授权提醒；后端记录项目、素材、任务与导出链路 |

Android 移动端适合该场景，是因为照片、视频、文本灵感和分享行为都高度移动化。相比把用户引向复杂后台，Android App 更适合承担即时交互、素材采集、创作引导和结果反馈；后端则负责重型生成、数据管理和系统稳定性。

# 四、产品与解决方案

## 1. 产品总体定位

映人生是一套以 Android 移动端为核心的 AI 故事内容创作解决方案。产品不是单一生成 Demo，也不是纯文本聊天机器人，而是围绕移动端创作流程，把“输入素材/文本 - AI 访谈 - 风格选择 - 故事草稿 - 分镜脚本 - 首版预览 - 导出/会员 - 作品沉淀”组织成闭环。

当前项目主张：

1. Android App 是用户主入口，承担移动采集、创作引导、结果确认与商业转化。
2. 后端服务是业务中枢，承担认证、项目、素材、AI 任务、预览、导出、订单、会员和运维能力。
3. 数据层沉淀项目、素材、草稿、分镜、任务、作品、订单和会员信息。
4. 算法层通过 DashScope 等模型能力支撑文本生成、图像生成、图生视频和 TTS 扩展。
5. 运维体系用于账号、权益、任务和模型配置管理，不作为对外 Web 平台宣传。

## 2. Android 端定位、核心功能、主要用户和使用场景

| 项目 | 内容 |
|---|---|
| Android 端定位 | 面向普通创作者、一线内容运营者、学生、机构工作人员的移动创作入口 |
| 核心功能 | 后端可用性检测、登录/注册、协议确认、首页、创作入口、场景选择、素材导入、照片上传、文本输入、AI 访谈、叙事风格选择、故事草稿确认、分镜展示、预览展示、导出方案、支付确认、导出状态、作品库、订单、会员中心、个人中心、机构入口预留 |
| 主要用户 | C 端创作者、小说/短视频创作者、校园师生、机构内容人员 |
| 使用场景 | 自拍角色穿越、名著融合、大纲扩写、小说转漫画分镜、小说转短视频脚本、文化内容移动创作 |
| 输出价值 | 降低 AI 创作门槛、实现移动采集与移动反馈、提升内容生产效率、形成数据和商业闭环 |

## 3. 后端服务定位、核心功能和支撑作用

后端服务负责 Android App 之外的业务能力，包括账号认证、用户资料、会员权益、场景配置、项目创建、素材上传、文件存储、故事草稿生成、分镜生成、预览生成、任务状态、作品生成、订单记录和运维后台能力。当前后端采用 FastAPI + SQLAlchemy，支持 MySQL 和 SQLite，并通过 DashScope SDK 调用文本、图像、视频和 TTS 模型。

需要特别说明：仓库中存在 `/admin` 运维页面，用于内部账号、会员级别和管理员权益维护。该能力应表述为“后端运维能力”或“内部运维页面”，不应包装成面向客户销售的 Web 平台或 Web 管理后台。

| 会员与运维 | 展示 Lite/Pro/Max、订单、个人资料 | 返回会员权益、后台维护账号和权限 | 权益、价格、账号状态 |

## 5. 用户完整使用流程

```text
打开 Android App
→ 后端可用性检测
→ 新手引导/协议确认
→ 登录或注册
→ 首页点击开始创作
→ 选择创作方式：角色穿越 / 大纲成文 / 小说改编
→ 选择具体场景：西游记角色穿越 / 红楼梦角色穿越 / 融合历史小说 / 原创故事小说 / 生成连环漫画 / 生成短视频
→ 上传人物照片或输入故事大纲/小说正文
→ AI 访谈补充设定
→ 选择叙事风格
→ 后端生成故事草稿
→ Android 端确认草稿
→ 后端生成分镜
→ Android 端展示漫画/短视频分镜
→ 后端生成预览
→ Android 端展示封面、预览信息和导出方案
→ 用户选择单次导出或会员权益
→ 后端创建订单/导出/作品记录
→ 作品库沉淀结果
```

# 七、核心创新点

## 创新点一：以 Android 移动端组织 AI 故事创作闭环

1. 现有问题：通用 AI 工具缺少移动端创作流程，普通用户难以从“灵感/照片/大纲”直接形成可展示内容。
2. 本项目方法：以 Android App 为入口，按“创作方式 - 场景 - 素材/文本 - AI 访谈 - 风格 - 草稿 - 分镜 - 预览 - 导出”组织流程。
3. Android 端如何体现：已实现首页、创作入口、素材导入、AI 访谈、风格选择、草稿确认、分镜、预览、导出、会员订单等页面。
4. 后端/数据/算法如何支撑：后端提供项目、素材、AI 生成、任务、作品、订单接口；数据层沉淀完整链路。
5. 技术或商业效果：降低创作门槛，强化导出和会员转化路径。
6. 壁垒与可复制难度：壁垒来自移动端流程设计、场景模板、生成链路、数据闭环和商业化组合，而非单点模型调用。
7. 当前验证情况：Android 与后端主链路已具备开发版骨架；真实用户转化数据【待补充】。
8. 创新类型：应用创新 + 集成创新。

## 创新点二：AI 访谈式设定补全，提高生成可控性

1. 现有问题：用户输入往往很短，大模型容易生成泛化内容；普通用户也不知道如何写高质量提示词。
2. 本项目方法：不同创作模式提供不同访谈问题，例如角色身份、照片气质、核心冲突、题材质感、输出重点等。
3. Android 端如何体现：`InterviewRoute` 通过移动端表单/问答形式收集回答。
4. 后端/数据/算法如何支撑：后端将访谈答案与主题文本、素材信息拼接为生成上下文，再生成故事草稿和分镜。
5. 技术或商业效果：提高生成结果与用户意图的一致性，减少用户反复重生成成本。
6. 壁垒与可复制难度：需要沉淀不同场景的问题模板、提示词策略和效果评估。
7. 当前验证情况：代码中已实现基础访谈问题和上下文拼接；效果评测【待补充】。
8. 创新类型：应用创新 + 工程优化。

## 创新点三：从故事草稿到分镜再到视频预览的分层生成链路

1. 现有问题：直接生成视频成本高、失败率高且难以修改；用户缺少中间确认节点。
2. 本项目方法：先生成故事草稿，再生成结构化分镜，最后生成首帧和短视频预览。
3. Android 端如何体现：用户先看草稿，再看分镜，再进入预览与导出方案。
4. 后端/数据/算法如何支撑：后端用 `story_drafts`、`storyboard_sections`、`preview_assets` 分层存储内容资产，使用异步任务管理预览生成。
5. 技术或商业效果：降低生成失败成本，提高可解释性和用户信任感。
6. 壁垒与可复制难度：需要把模型输出规范化为可存储、可展示、可编辑的数据结构。
7. 当前验证情况：故事草稿、分镜和预览接口已实现；真实视频效果依赖 DashScope Key 与模型稳定性。
8. 创新类型：集成创新 + 工程优化。

## 2. 移动端差异化优势

1. Android 端增强一线触达：用户可以直接从相册选择照片、输入故事片段、查看生成结果，不需要复杂桌面工具。
2. Android 端增强移动操作：创作流程被拆成连续步骤，普通用户可以按提示完成创作。
3. Android 端增强数据采集：照片、文本、访谈答案都可在移动端采集，并与后端项目 ID 关联。
4. 后端服务增强数据管理：后端统一管理项目、素材、任务、作品、订单和会员权益。
5. Android 与后端协同增强商业交付：移动端负责转化，后端负责稳定生成、计费记录和运维支撑。

映人生并不适合在所有场景中替代通用 AI 工具或专业内容团队。其差异化优势在于：面向“普通用户/轻量创作者/校园与机构内容人员”的移动端故事创作流程，特别适合角色穿越、名著融合、小说改编、漫画分镜和短视频脚本等细分场景。

# 十七、社会价值与长期愿景

## 1. 产业价值

映人生将生成式 AI 能力从单点模型调用转化为可交付的移动端产品流程，有助于推动数字内容生产工具化、移动化和低门槛化。项目可服务短视频、小说、漫画、教育、文旅和文化传播等内容产业环节。

## 2. 用户价值

对普通用户而言，项目降低了故事创作、分镜设计和视频预览的门槛；对创作者而言，项目提高了从灵感到脚本再到预览的效率；对机构而言，项目提供了移动采集和后端生成结合的内容生产工具。

## 3. 社会价值

项目可用于传统文化、名著改编、历史故事、校园创意写作等场景，使文学和文化内容以更轻量、更互动的方式被年轻用户理解和再创作。同时，项目需要坚持版权、肖像、未成年人保护和 AI 生成标识等合规要求。

## 4. 人才培养价值

项目覆盖 Android、后端、数据库、AI 模型接入、产品设计、商业模式、测试运维和合规治理，适合作为高校创新创业、软件工程实践、人工智能应用实践和数字文化创作课程的综合项目。

## 5. 生态价值

长期看，映人生可沉淀场景模板、提示词、分镜结构、行业案例、创作数据和机构交付经验，形成面向细分内容场景的生态接口。后续可开放 API、模板市场、机构账号和合作伙伴计划。

## 6. Android 移动端解决方案的长期价值

Android 移动端使项目能够持续贴近用户真实创作场景：手机相册是素材入口，移动输入是灵感入口，任务通知是反馈入口，导出分享是传播入口。后端服务、数据能力、算法能力和运维体系则保证移动端不是孤立 App，而是可持续迭代、可规模部署、可商业转化的完整解决方案。

| 你们是不是又做了一个通用 AI App？ | 不是。映人生不是通用聊天或单点生成工具，而是以 Android 移动端为入口的 AI 故事内容创作解决方案。我们重点解决从自拍、大纲、小说到角色设定、故事草稿、分镜和预览的生成链路。 |
| 为什么强调 Android 端？ | 因为项目的素材采集、文本输入、即时预览和分享都天然发生在移动端。Android 端负责触达和交互，后端负责重型生成和数据管理，两者组合形成闭环。 |
| 你们有没有 Web 平台或管理后台？ | 当前项目没有面向用户的 Web 平台，也不把 Web 端作为产品卖点。仓库中有内部 `/admin` 运维页面，用于账号和权益维护，定位是后端运维能力，不是对外 Web 管理后台。 |
| AI 生成能力是不是只是在调用第三方模型？ | 模型调用是底层能力之一，但项目价值在于把场景、访谈、风格、草稿、分镜、预览、导出和会员组织成移动端产品流程，并沉淀数据结构、任务机制和商业闭环。 |
| 如果大厂也做类似功能，你们优势是什么？ | 我们不试图全面替代大厂工具，而是聚焦名著融合、角色穿越、小说改编、校园创作、文旅内容等细分场景。优势来自场景模板、移动端流程、行业交付和数据闭环。 |
| 当前项目进展到什么阶段？ | 已完成 Android 多模块工程和后端 FastAPI 服务骨架，具备登录、创作流程、素材上传、故事草稿、分镜、预览、导出、订单、会员等开发版链路。真实用户数据、支付接入、合规材料和试点案例仍需补充。 |
| 如何保证生成内容质量？ | 采用分层生成：先访谈补充设定，再生成故事草稿，再生成分镜，最后生成预览。每一步都给用户确认机会，后续会建立效果评测集、提示词版本管理和人工编辑能力。 |
| 如何控制视频生成成本？ | 早期限制免费额度，优先生成文本和分镜，只有用户确认后再生成高成本图像/视频。商业上通过会员、导出、额度包覆盖模型成本，并通过缓存、队列和失败策略降低浪费。 |
| 如何处理肖像、版权和 AI 合规？ | Android 端将嵌入授权确认、AI 生成标识说明、第三方肖像和未成年人提醒；后端记录素材、生成和导出链路。正式上线前需要补充隐私政策、用户协议、内容审核和删除机制。 |
| 你们的收入模式是什么？ | 早期以单次高清导出和会员订阅为主，中期面向校园、文旅和内容团队做移动端解决方案交付，后期扩展 API、私有化部署、模板生态和运维服务。 |
| 为什么客户愿意付费？ | C 端为省时间、获得可分享结果和高清无水印导出付费；机构为降低内容生产成本、提高移动采集和批量创作效率付费。 |
| 财务预测依据是什么？ | 当前没有真实收入数据，因此采用保守测算假设，并明确标注非真实经营结果。后续会根据真实用户转化、模型成本和机构项目数据修正。 |
| 如何获取第一批用户？ | 先从校园社团、网文/短视频创作者、AI 创作社群和文旅小场景试点切入，用作品案例验证需求，再通过渠道合作和机构交付扩大。 |
| 后端稳定性怎么保证？ | 当前已有任务状态、数据库持久化和健康检查。后续需要补充任务队列、对象存储、限流、日志监控、告警、备份和部署脚本。 |
| 你们最核心的风险是什么？ | 核心风险是生成质量、模型成本、用户付费意愿和合规。对应措施是场景化模板、分层生成、成本控制、真实用户验证和合规材料建设。 |
